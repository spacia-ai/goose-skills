# goose-skills (community registry)

Canonical seed content for the **public** [`spacia-ai/goose-skills`](https://github.com/spacia-ai/goose-skills)
repository — the community registry that `goose skills install <name>` reads
from. This directory tracks the same files inside the main `goose` repo so the
two stay in lockstep during early development.

## Layout

```
community-skills/
├── README.md                         (this file)
├── index.json                        (auto-generated by CI; checked in)
├── schema/
│   └── index-v1.json                 (JSON Schema for index.json)
├── .github/workflows/
│   └── regenerate-index.yml          (CI workflow that produces index.json)
├── extensions/                       (skills associated with a specific MCP)
│   ├── exa/SKILL.md                  (name: exa            — operator's manual)
│   ├── github/SKILL.md
│   ├── supabase-mcp/SKILL.md
│   └── slack-mcp/SKILL.md
└── standalone/                       (skills with extensions: [])
    ├── code-review/SKILL.md
    ├── debugging-rust/SKILL.md
    └── writing-prd/SKILL.md
```

## Frontmatter contract (skill author cheatsheet)

```yaml
---
name: <unique-name>                   # required
description: <one-line>               # required
extensions: [exa]                     # soft matchlist (M:N hint surface)
requires: [exa]                       # hard activation gate
tools: [exa__search]                  # tool filter (must reference an ext above)
isolated: false                       # if true, deactivates other active skills
tags: [search, web, research]         # search metadata
min_goose_version: "1.33.0"           # SemVer gate; install refuses if older
---

# Body — markdown instructions
```

## How `index.json` is built

The CI workflow (`.github/workflows/regenerate-index.yml`) walks every
`SKILL.md`, parses frontmatter, computes file SHA256s, and emits a
machine-readable catalog at `index.json` in the repo root. `goose skills`
fetches this on every `install` / `list --available` call (cached 1 hour
client-side).

## Bootstrap step (one-time, to be done by maintainer)

1. Create the public repo at <https://github.com/spacia-ai/goose-skills>.
2. Copy every file under this directory to the new repo, preserving paths.
3. Push to `main`. The CI workflow generates `index.json` automatically.
4. (Optional) Tag releases per skill: `exa@v1.0.0`, `code-review@v1.0.0`, etc.

After bootstrap, this directory in the main `goose` repo can either be
deleted (if you want a strict separation) or kept as a development mirror
that gets PR'd alongside core-side skill API changes.

## Contributing

PRs welcome. Each PR must:

- Touch only one skill (one directory, one `SKILL.md` + its assets).
- Include a frontmatter `description` that's a single, declarative sentence.
- Declare `requires:` only for extensions the skill genuinely cannot function
  without. Use `extensions:` (soft) for "works best with."
- Set `min_goose_version` to the current goose release at PR time.
- Pass `validate-skill-pr.yml` (frontmatter parser + tools-extension cross-ref).
